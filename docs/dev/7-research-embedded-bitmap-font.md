## 1. 背景

当前运行时使用静态链接的 `libfreetype.a` 从内嵌字体中实时栅格化文字。虽然 `ldd` 不显示 `libfreetype.so`，但默认构建仍依赖系统 FreeType 静态库和头文件。

## 2. 推荐方案

- 将当前界面所需字号和字符预先生成为项目内 C 字形表。
- 运行时只读取字形表并做 CPU alpha blending。
- 默认 `make` 不再依赖 FreeType、字体文件或字形生成器。
- 保留开发用生成器，后续变更字体或文案时可重新生成字形表。

## 3. 取舍

- 优点：默认构建和运行都不依赖 FreeType；二进制继续只依赖 `libdrm` 和 `libc`。
- 缺点：只支持预生成字符集；新增 UI 文案、字号或需要中文用户名输入时要重新生成字形表。
- 当前界面文案固定，用户名输入主要覆盖 ASCII，适合该方案。

## 4. 风险与边界

- 预生成字符集包含 ASCII 可打印字符和当前 UI 中文文案字符。
- 密码显示为 `*`，无需覆盖密码原文显示。
- 不支持运行时任意 Unicode 字符栅格化。
- 不运行实机会接管显示输出的程序，只做构建、帮助路径和动态依赖验证。
